# ピットストップ・耐久戦 設計 v2

置き場：`docs/設計/ピットストップ.md`
台詞：`data/radio.json` の `pit_stop` 節と `commentary.json`（取り込み済み。追加分のファイルは消した）

実装：`src/engine/race.js` の `ENDURANCE` と `PIT`（**数値はこの2つだけに置く**）、
`src/ui/setup.html`（燃料の3択）、`src/ui/race.html`（合図とボックス）。
テストは S17〜S20（`src/engine/season.test.js`）と 30（`src/engine/race.test.js`）。

## 決めたこと

1. **耐久は6戦のうち1戦だけ。** シーズン第4戦を周回数2倍にする。コースは通常の巡り順のまま
2. **燃料の量はプレイヤーが決める。** 耐久戦のセッティング画面にだけ「燃料」の項目が出る。3択：満タン／必要分＋余裕／ぎりぎり。他の5戦は今までどおり自動
3. **ピットインの合図はプレイヤーが出す。** レース中の無線パネルに「次の周、入れ」を置く。ハルカは抵抗する。押し切らなければ入らない

## 燃料

- 耐久戦は満タンでも走り切れない距離にする（満タン＝全周回の **65%**）。必ず一度は入る
- 満タン：重い。序盤が遅い。1回のピットで届く
- 必要分＋余裕：中間。1回のピットで届くが、ピットの周を遅らせる余裕は少ない
- ぎりぎり：軽い。速い。ピットを1周でも遅らせると届かない。節約走行と組めば届く
- 燃料の重さは既存の計算（fuel）を使う。ピットで給油する量は「満タンまで」で固定
- 「燃料、節約」の指示：燃費 −10%、周のタイム +0.3%。押している間だけ。ハルカは嫌がる

## ピットイン

- ピット窓：燃料が残り 30% を切った周から開く。開いたらピットが一言（`window_open`）
- プレイヤーが「次の周、入れ」を押す → ハルカが抵抗（`resist`）→ もう一度押す（`insist`）→ 折れる（`comply`）→ 次の周に入る
- 一度押しただけで放置すると入らない。ハルカは走り続ける（`stay_out`）。燃料が尽きれば fuel_out。**これで燃料切れに到達できる**
- 入るときに「給油のみ／給油＋タイヤ交換」を選ぶ。タイヤ交換は摩耗をリセットするが +8秒
- 停止時間：静止 20秒 ＋ 給油（残量に応じて 4〜10秒）＋ タイヤ交換 8秒。ピットロードの通過で別に 15秒
- 停止中は画面に秒数のカウント。ハルカの独り言（`in_box`）が2〜3本流れる
- 出た直後は冷間タイヤ（既存の cold_tire の計算）と満タンの重さ

## AI

- AI も必ず一度入る。入る周は性格で決める：攻め型は遅く（残り 15%）、堅実は早く（残り 35%）、他は 25%。種で ±1周散らす
- AI はタイヤ交換の有無も性格で固定（攻め型＝交換しない、堅実＝交換する）
- AI の停止時間は自車と同じ式

## 画面

- セッティング画面：耐久戦のときだけ「燃料」の行を出す。選ぶとハルカの反応（`fuel_*`）。
  何周ぶん積むことになるかを数字で出す（満タンでも足りないことが読めるように）
- レース画面：無線パネルに「次の周、入れ」「燃料、節約」の2つ。窓が開くまでは押せない（灰色）
- ピット中：順位表はそのまま動く（止まっている間に抜かれるのが見える）
- レース後：ピットで失った秒数と、順位の入れ替わりを結果に一行

## 実況・解説

- 既存の `pit` に追加。新設 `undercut`（ピットが絡んだ順位変動）、`fuel_save`（節約指示を出したとき）、`no_stop_finish`（無給油で走り切った）

## 確定値

**数値はここと `src/engine/race.js` の `ENDURANCE` / `PIT` にしか無い。** 画面には書かない。

### 耐久戦（`ENDURANCE`）

| 名前 | 値 | 意味 |
|---|---|---|
| `round` | 4 | シーズン6戦のうち第4戦が耐久 |
| `lapFactor` | 2 | 周回数は通常の2倍（クラス1なら 8→16、クラス5なら 16→32） |
| `tankShare` | 0.65 | **満タンで走れるのは全周回の65%。** 基準の車（`fuel_consumption` 0）で測る |
| `load.full` | 1.00 | 満タン（＝全周回の65%ぶん） |
| `load.margin` | 0.80 | 必要分＋余裕（52%ぶん） |
| `load.tight` | 0.46 | ぎりぎり（29.9%ぶん） |
| `save.fuel` | 0.90 | 「燃料、節約」で燃費 −10% |
| `save.lap` | 1.003 | 同じく周のタイム +0.3% |

**0.65 なのは、残り35%で入る堅実型の AI が一度の給油で届くため。**
1回のピットで走れる距離は `(1 − 入る割合) × tankShare + tankShare` なので、
これが1.0以上になる割合の上限は `2 − 1/tankShare`。0.60 では 0.333 までしか許さず
堅実型（0.35）が届かないが、0.65 なら 0.462 まで許すので 15/25/35 をそのまま使える。

満タンの量は**基準の車で測る**ので、燃費の悪い車はこれより短い距離しか走れない。
`fuel_consumption` がいちばん効くのがこの戦になる。

**3択がなぜ違うものになるか。** 給油は「満タンまで」で固定なので、残して入ったぶんは捨てる。
だから**引っぱるほど総距離が伸びる**。1回のピットで走れる距離は「積んだ量 ＋ 満タン1杯」。

| 方針 | 1回のピットで走れる距離 | 結果 |
|---|---|---|
| 満タン | 0.65 + 0.65 = **1.30** | 余裕。窓が開いてすぐ入っても届く |
| 必要分＋余裕 | 0.52 + 0.65 = **1.17** | 届く。早く入っても届くことがある（クラスによる） |
| ぎりぎり | 0.299 + 0.65 = **0.949** | **届かない。** 節約（×1.111）と組んで 1.054 で届く |

クラスごとの周ぶん（テスト S17 が毎回出す）。満タン／余裕／ぎりぎりの順。

| クラス | 周回 | 積む量（周ぶん） | 1回のピットで走れる周回（ぎりぎりは節約込み） |
|---|---|---|---|
| 1 | 16 | 10.4 / 8.3 / 4.8 | 20.8 / 18.7 / 15.2（16.9） |
| 2 | 20 | 13.0 / 10.4 / 6.0 | 26.0 / 23.4 / 19.0（21.1） |
| 3 | 24 | 15.6 / 12.5 / 7.2 | 31.2 / 28.1 / 22.8（25.3） |
| 4 | 28 | 18.2 / 14.6 / 8.4 | 36.4 / 32.8 / 26.6（29.5） |
| 5 | 32 | 20.8 / 16.6 / 9.6 | 41.6 / 37.4 / 30.4（33.7） |

`tankShare` を 0.60 から 0.65 に上げたぶん、**「必要分＋余裕」は入る周の幅が広がった**。
0.60 のときは入れる周がほぼ1周しか無かったが、いまは早めに入っても届くクラスがある
（クラス1・4は届き、2・3・5は届かない）。満タンとの差は重さと、入らなければならない周の早さになる。

### ピット（`PIT`）

| 名前 | 値 | 意味 |
|---|---|---|
| `window` | 0.30 | 満タンに対する残量がこれを切ったらピット窓が開く |
| `stop.lane` | 15秒 | ピットロードの通過 |
| `stop.still` | 20秒 | 静止しているぶん |
| `stop.fuelMin` / `fuelMax` | 4〜10秒 | 給油。残量が少ないほど長い |
| `stop.tyre` | 8秒 | タイヤ交換を足したときの増分 |
| `ai.attack` / `other` / `steady` | 0.15 / 0.25 / 0.35 | AI が入る残量。攻め型は引っぱり、堅実は早く入る |
| `ai.jitter` | ±1周 | 入る周を種で散らす |
| `aiTyre` | attack のみ false | 攻め型は8秒を惜しんでタイヤを替えない |

停止時間 ＝ `lane + still + (fuelMax − (fuelMax − fuelMin) × 残量割合) + (替えるなら tyre)`。
空に近い状態で給油のみなら **45秒**、タイヤも替えれば **53秒**。

### 保険：入らなければ止まるときだけは、回数を問わず入る

AI が燃料切れで止まるのは見ていて意味が無いので、`aiWantsPit` に保険を置いた。
**性格の割合で入るのは1回だけ**だが、入らなければ次の周を走れないときは何度でも入る。
発火は `car.pitForced` に数える。**噛み合っていれば、ここはほとんど発火しない。**

### 二度入る AI は、燃費（`fuel_consumption`）で決まる

`tankShare` 0.65 と 15/25/35 の組み合わせでは、**基準の車なら全員が1回で足りる**
（クラス1は AI 全車が `fuel_consumption` 0 なので、45レース中ずっと二度入りが0台）。

残るのは燃費。満タンは基準の車で測るので、燃費の悪い車の満タンはそのぶん短い。

| `fuel_consumption` | 1周の消費 | 満タンで走れる距離 | 1回のピットで |
|---|---|---|---|
| 0 | ×1.00 | 全周回の 65% | 130% ○ |
| 4 | ×1.20 | 54% | 108% ○（ただし早く入ると届かない） |
| 6 | ×1.30 | 50% | 100% △ |
| 14 | ×1.70 | 38% | 76% ×（**二度でも足りず三度入る**） |

クラス2以上の AI はノートのパーツを積むので `fuel_consumption` が 0〜14 まで散る。
3方針×3シード×5クラス（45レース）で **二度入った AI は1レースあたり 4.40 台（最大9台）**。
内訳は other 135 / steady 42 / attack 21 で、**二度入った車はすべて `fuel_consumption` 4 以上**、
0 の車は一度も二度入っていない。つまり原因は入る割合ではなく燃費。

目標（1レースあたり0〜1台）に収めるなら、どちらかを決める必要がある。**まだ採っていない。**

1. **タンクを車ごとに測る** — `enduranceTank(laps, stats)` にして、どの車も自分の燃費で
   全周回の65%を走れるようにする。試したところ45レースで二度入りは **0台**、保険の発火も
   1レースあたり0.33回まで落ちた。代わりに `fuel_consumption` は**距離ではなく重さ**にしか
   効かなくなる（燃費の悪い車は同じ距離を走るのに多く積む＝重い）
2. **AI の燃費に上限を置く** — 耐久戦では `fuel_consumption` の高いパーツを AI に積ませない
   （`rivals.js`）。自車側の「燃費が距離に効く」は残る
3. **今のまま** — 燃費の悪い車が余計に止まるのは現実の理屈どおり。ただし AI の1/3前後が
   45〜53秒を余計に払うので、耐久戦だけプレイヤーが有利になる

### 通しで走らせた結果（自車は純正・パーツなし）

| クラス | 満タン | 必要分＋余裕 | ぎりぎり＋節約 |
|---|---|---|---|

| 2（20周・12台） | 平均 9.0位（pit 12周目） | 平均 **8.7位**（pit 10周目） | 平均 9.7位（pit 6周目） |
| 3（24周・16台） | 平均 13.7位（pit 15周目） | 平均 **13.3位**（pit 12周目） | 平均 13.7位（pit 7周目） |
| 4（28周・20台） | 平均 13.0位（pit 18周目） | 平均 13.0位（pit 14周目） | 平均 13.0位（pit 9周目） |

（実際には届く見込みが立った時点で切れば、そのぶん速い）。
