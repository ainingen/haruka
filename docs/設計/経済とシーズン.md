# 経済とシーズン

お金・購入・消耗・シーズン進行・スポンサー・セーブ。
「勝ち続けないと維持できない」緊張を作る層。数値はすべて `data/economy.json` にあり、コードに埋めない。

## 状態（ゲームの進行）

進行はひとつのオブジェクト `state` で持ち、画面間は URL の `s=` パラメータで持ち回る
（ブラウザストレージは使えない前提。PLiCy の制約）。
**シリアライズは `src/engine/save.js` の1箇所だけ。** 将来 PLiCy のセーブ機能に置き換えるときも、ここだけを触る。

```
state = {
  v: 1,                          // 形式のバージョン
  money: 60000,
  cls: 1, tier: 0,               // クラス、スポンサー段階
  owned: ["engine_intake_01"],   // 所有パーツ
  cond: { "engine_intake_01": 94 },   // 所有パーツの耐久（現在値）。無ければ満タン
  setup: { race: { parts: [...], settings: {...} }, quali: {...} | null },
  season: {
    year: 1,
    rounds: [ { course: "misaki", laps: 8, result: { pos: 4, points: 5, ... } | null }, ... ×6 ],
    next: 0,                     // 次に走るラウンド
    points: { me: 12, ai0: 18, ... },   // 今シーズンのポイント
    symptoms: { understeer: 3, ... },   // 今シーズンに出た情報系トリガーの回数（オフシーズンのノート用）
    note: "今年は前が逃げてばっかりだった" | null,   // 前シーズンの終わりにハルカが書いた一行
  },
  sponsor: { tier: 1, id: "local_garage" } | null,
}
```

画面の役割：

| 画面 | 役割 |
|---|---|
| `season.html` | ハブ。今シーズンの6戦、ポイント表、所持金、次戦へ。シーズン終了時は昇降格とオフシーズン |
| `setup.html` | 次戦のセッティング。所持金と所有パーツ。購入・売却・修理・装着 |
| `race.html` | 予選・決勝。終わったら収支（賞金・スポンサー料・参加費・修理費）と消耗を state に反映 |

流れ：`season.html` → `setup.html` → `race.html?session=quali` → `race.html?session=race` → `season.html`。
どの画面も、受け取った `state` に自分の変更を足して次の画面へ渡す。

## お金

- **所持金**を持つ。初期値は `initial_money`。クラス1の中古パーツが2〜3点買える程度
- **パーツは購入して所有する。** 所有していれば装着・取り外しは自由。一度買えば何度でも付け外しできる
- 購入できるのは規定（`class_required`）とスポンサー段階（`sponsor_tier`）を満たすパーツだけ。
  買えないときは理由を出す（クラス不足、段階不足、資金不足）
- **売却は買値の 40%**（`sell_ratio`）。序盤の資金繰りに使える。装着中でも売れる（外れる）
- 収入：**賞金**（クラス × 順位。`prize`）＋ **スポンサー料**（段階ごとに固定。`sponsor_fee`。レースごと）
- 支出：パーツ購入、**参加費**（クラスごと。`entry_fee`。予選と決勝で1回）、**修理費**
- リタイアしても参加費は払う。賞金は無い

目安：**クラス1で6戦走って、中位なら2〜3点買い足せる。上位なら5点。** 実際に通しで走らせて確かめる（下の「数値の確かめ方」）。

## 消耗と修理

- パーツは `durability`（parts.json）を上限とする耐久を持つ。**レースごとに減る**
- 減る量は `wear.per_race` を基準に、**車全体の `reliability` が低いほど速く減る**
  （`per_race × (1 + per_reliability × max(0, −reliability))`）。無理なチューンは速く壊れる
- **リタイアしたレースは減りが `retire_multiplier` 倍。** 修理費も跳ねる
- 装着していないパーツは減らない
- 耐久が `threshold` を切ると **効果（`effects`）が落ちる**。閾値でちょうど 100%、0 に近づくほど 50% まで直線で落ちる。
  副作用（`side_effects`）は落ちない——摩耗したタービンも重さと熱はそのまま
- **耐久 0 は故障。** そのレースは効果なし（副作用だけ残る）。走ることはできる
- **修理は費用を払って耐久を上限まで戻す。** 費用は `price × repair_rate × 減った割合`、
  ただし**そのクラスの5位の賞金を上限**とする。高価なパーツでも中位の賞金1回ぶんで必ず直せる。
  修理せずに走るのも選べる（安く済ませたいとき、シーズン最終戦のとき）
- 計算への反映は `applyWear(part, durability)` が返す「効果を縮めた写し」を `buildPerformance` に渡す。
  エンジンの合成式は変えない

## シーズン

- **1シーズン＝6戦**（`rounds_per_season`）。そのクラスで走れるコースから引く。同じコースが2回入ることもある
- 周回数はクラスごと（`laps`）。上のクラスほど長い
- 出走台数はコースの `grid`（クラス別）。相手は `data/rivals.json` の先頭から
- 各戦は**ポイント制**：1位10、2位8、3位6、4位5、5位4、6位3、7位2、8位1（`points`）。リタイアは 0
- ポイントは自車も AI も積む。AI のポイントは、その戦の実際の着順から
- **シーズン終了時**：
  - ランキングが `promote[cls]` 位以内なら昇格（8台中3位以内、20台中5位以内など）
  - 下から `relegate[cls]` 台に入っていたら降格。**クラス1からは下がらない**
  - 昇格すると車体が変わることがある（クラス1→2 でハッチバック→セダン）。装着中のパーツはそのまま持つが、
    規定外になるものは計算から外れる（既存の仕様）
- **オフシーズン画面**（`season.html` のシーズン終了状態）：
  ハルカがノートに一行書く。その年に一番多かった情報系トリガーから生成（`data/radio.json` の `season_note`）。
  次のシーズンの最初にこの一行を読み返す
- 新しいシーズンの6戦は、昇降格後のクラスで引き直す

## AI の構成

AI は**自車の構成を参照しない。** 名簿（`data/rivals.json`）の強さと性格から、固定の構成を持つ（`src/engine/rivals.js`）。

3段階とも**同じノート**（`data/notes.json` のそのコース・クラスの基準セッティング）を見る。
違うのは、そのうち何点を積めるか。**金の無いチームほど高いパーツから欠ける**ので、
ノートを安い順に並べて頭から取る。

| 強さ | 構成 | ノート10点なら |
|---|---|---|
| 遅い | ノートの3割（切り捨て。最低1点） | 3点 |
| 並 | ノートの7割（四捨五入） | 7点 |
| 速い | ノート全点 ＋ 性格に合うパーツ 2〜3点（直線型＝ギア比・出力、コーナー型＝足・空力、低速型＝ブレーキ・LSD） | 10点＋2〜3点 |

- 遅い・並の点数は**ノートの長さだけで決まる**（種で散らさない）。速いが足すパーツだけ
  シーズン開始時の種（`season.rivalSeed`）で確定し、そのシーズン中は固定。
  state には種だけを持ち、構成はそこから決定的に作り直す（URL を長くしない）
- セッティング（連続値）は3段階とも同じ。金が要らないので、貧乏でも詰められる
- 基準はコースごとにノートを引き直す。そのコース・クラスのノートが無ければ下のクラスの
  ノート、それも無ければ同じクラスの別コースのノートを借りる（クラス5はクラス3〜4のノートの上に、
  速いだけがクラス5のパーツを足す）
- **遅いを「純正＋安物1〜2点」にしていたときは、これが成立しなかった。** ノートを持つ群と
  持たない群に場が割れ、間に車がいないので、自車が3点買っても5点買っても同じ位置に落ちた
  （クラス3の実測で 8.89 位と 8.50 位）。段差を連続にするために、遅いもノートを見る
- **AI も規定内のパーツしか使わない。** スポンサー段階はクラス − 1 とみなす
- 技量は強さで ±5、安定性と好みのバランスは個体差。車の性格（tune の数値）は持たない。
  性格はパーツの選び方に出る

だから、ノート通りに揃えれば「並」と互角、それより賢く選べば「速い」に届き、序盤の2〜3点では後ろに付く。
購入が順位に効く。

## スポンサー

- スポンサー段階は「シーズン成績」と「クラス」で上がる。**下がらない**

| 段階 | 条件 |
|---|---|
| 1 | クラス2に昇格した時点 |
| 2 | クラス3で1シーズン完走（6戦すべて出走） |
| 3 | クラス4でシーズン3位以内 |
| 4 | クラス5に昇格 |

- 会社は架空名。段階ごとに3社程度（`data/sponsors.json`）、段階が上がったときにランダムに1社が付く。
  地元の整備工場、ラーメン屋、地方の運送会社、家電量販店、タイヤメーカー……
- スポンサー料は段階ごとに固定（`sponsor_fee`）。レースごとに入る
- スポンサーが付くと、レース開始の実況が「○○のサポートを受ける神谷ハルカ」と言う（`commentary.json` の `sponsor_intro`）
- 段階0（自腹）のあいだは何も言わない

## 画面

### setup.html

- 図面の見出しに**所持金**。部品表の各行に耐久（%）と、閾値を切っていれば注意
- パーツ選択モニターのフッターで「購入」と「装着」を分ける：
  - 未購入：価格と「購入」。買えなければ理由（クラス・段階・資金）
  - 購入済み：緑の印と「装着」。装着中なら「外す」「売却」
  - 耐久が減っていれば「修理 ¥…」
- 出走ボタンは、そのラウンドのコースと周回数で固定（シーズン中はコース選択を出さない）

### season.html（新設）

- 上：年、クラス、所持金、スポンサー
- 6戦の一覧：コース、周回、結果（順位・ポイント・収支）。次に走る戦を強調
- ポイント表：上位＋自車の前後
- 「次戦のセッティングへ」→ `setup.html`
- 最終戦が終わっていれば：昇格／降格／残留の判定、ハルカのノートの一行、「次のシーズンへ」

### race.html

- 結果に**収支**：賞金、スポンサー料、参加費、修理費（消耗ぶんの見積もり）、差し引き
- 「シーズンへ戻る」が state を持って `season.html` へ。予選なら「決勝へ」に state を渡す

## セーブ

- 状態は `s=` パラメータ1つ。`save.js` の `encode(state)` / `decode(str)`。
  中身は短いキーの JSON を base64url にしたもの。長くなるようなら圧縮はここだけ変えればいい
- `v` でバージョンを持つ。古い形式は `decode` が読み替える。未来の形式は読まない（null）
- `s` が無い画面は新しいゲームを始める（`newGame()`）。`season.html` は新しいシーズンも組んで、
  URL を `history.replaceState` で書き換える（再読み込みしても進行が残る）
- 長さの目安：終盤の大きな state（クラス5、20台、6戦すべて結果あり、所有20点、予選セッティングあり）で
  **約 3,500 文字**。現代のブラウザは数万文字まで持つ。テスト E7 が 4,000 を超えないか見張る。
  超えたら `encode` を圧縮に変える。画面は触らない
- 開発用の旧リンク（`race.html?cls=&parts=…`）は `legacyState` が読む。`s` があればそちらが優先

## 数値の確かめ方

`tools/simulate-season.mjs`（開発用。配布物に含めない）が、指定クラスで1シーズンを通しで走らせ、
各戦の順位・賞金・参加費・修理費と、シーズン後の所持金を出す。

```
node tools/simulate-season.mjs --cls 3 --seed 1 --strategy notes --parts 3
```

**このツールは画面の決勝と同じ経路を通る**（`season.js` の `simulateField` → `race.js` の `runField`）。
予選でグリッドを決め、全車を同じ場で 0.05 秒ずつ進めるので、スタートの遅れも混雑もそのまま入る。
かつては各車を `simulateRace` で独立に走らせる近似だったが、それはもう使っていない。

方針は3つ。`none`（何も買わない）、`notes`（親父のノート通りに、安い順に毎戦買える範囲で。
`--parts N` で点数を止められる）、`smart`（6戦のコースを時間比で見て効く効果を採点し、5点まで買う）。
初期資金は `--money`。既定はクラス1が新規開始の資金、2以上はそのクラスの1位賞金×2
（下のクラスを勝ち上がってきた人が、最初の買い物で2〜3点は選べる額）。

### 目安と、2026-09-14 の結果（3方針×3シード、平均着順）

目安は台数に按分する。買わない＝下1/4、3点＝台数×(5〜6)/8、ノート全点＝並より上。

| クラス | 台数 | ノート | 遅い | 並 | 買わない | 3点 | 5点 | ノート全点 |
|---|---|---|---|---|---|---|---|---|
| 1 | 8 | 4〜5点 | 1点 | 3〜4点 | 6.39 | 3.78 | 2.89 | 2.89（5点） |
| 2 | 12 | 7〜8点 | 2点 | 5〜6点 | 10.45 | 8.72 | 7.61 | 6.17（10点） |
| 3 | 16 | 10〜13点 | 3点 | 7〜9点 | 14.56 | 10.67 | 9.72 | 7.89（10点） |
| 4 | 20 | 13〜16点 | 3〜4点 | 9〜11点 | 16.06 | 12.34 | 10.61 | 4.60（19点） |
| 5 | 20 | 13〜16点 | 3〜4点 | 9〜11点 | 15.39 | 11.78 | 9.67 | 3.88（24点） |

「ノート」はそのクラスのノートの点数、「遅い」「並」はそこから実際に積まれる点数。
「3点」「5点」はノートの安い順にその点数だけ買った場合。クラス5には自前のノートがまだ無く、
クラス4のものを借りている。

読み方：**買わないと必ず下位に沈み、3点でようやく遅い車を抜きはじめ、ノートを揃えると並の上に出る。**
上のクラスほどノートが長いので、同じ「3点」でも意味が軽くなる。これは意図した通り
（クラス4で3点＝ノートの2割）。

### まだ合っていないところ

- **クラス1の「3点」が強すぎる**（3.78。目安は 5.0〜6.0）。ノートが4〜5点しかないので、
  3点でほぼ揃ってしまう。クラス1のノートを長くするか、目安のほうを直すか
- **ノートが買い切れない。** 1シーズンで使える金（開始＋中位6戦の手残り）に対するノート総額は、
  クラス1が 138k/120k、クラス2が 572k/340k、クラス3が 1,598k/650k、クラス4が 6,327k/3,370k。
  クラス2以上は1シーズンでは揃わない（クラス4・5の「ノート全点」が上位なのは、
  複数シーズンぶんの資金を渡して測っているから）

### 消耗と修理

- 1レースの消耗は `wear.per_race` 6 ＋ 信頼性ぶん。リタイアすると `retire_multiplier` 3 倍
- 効果が落ちはじめるのは耐久 `threshold` 30 から。0 で故障
- 修理費は**減った割合 × 価格 × `repair_rate` 0.15**、**上限はそのクラスの5位の賞金**。
  高価なパーツでも、中位の賞金1回ぶんで必ず直せる

### 名簿の比率

名簿（`data/rivals.json`）は先頭から順に使う。クラスが上がると台数が増え、その差分が名簿の続きになる。

| クラス | 台数 | AI | 速い | 並 | 遅い |
|---|---|---|---|---|---|
| 1 | 8 | 7 | 2 | 2 | 3 |
| 2 | 12 | 11 | 3 | 3 | 5 |
| 3 | 16 | 15 | 4 | 4 | 7 |
| 4・5 | 20 | 19 | 5 | 7 | 7 |

クラス2・3が足す4台は 速い1・並1・遅い2（クラス1の比率をそのまま伸ばす）。
**クラス4が足す4台は 速い1・並3・遅い0** — 上のクラスほど場が揃うほうが、自車が3点買った程度では
上がれない。遅いを足すと、3点買っただけで中位に届いてしまう（20台で 10.6 位まで上がった）。

### 技量の差

速い +3、遅い −2（`rivals.js` の `AI_STRENGTH`）。**この幅は動かさない。**

差はパーツで付ける、というのがこのゲームの方針で、技量はその差を見えにくくする方向にしか働かない。
遅いの技量を大きく下げると、パーツの差を打ち消して純正の自車が遅い車に勝ってしまう
（「買わなくても勝てる」になる）。逆に上げると、パーツを揃えても追いつけなくなる。
順位が目安から外れたときに直すのは**名簿の比率と賞金**で、技量には戻らない。

このほか、AI ごとの個体差として技量 ±3、安定性 ±15、好みのバランス ±2 が乗る（種から決定的に）。
